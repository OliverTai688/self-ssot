## 1. 目標與來源優先序

以現有 Personal OS 的身分與空間概念為底座，讓宇星與 Lily 能在圓展工作日誌記錄、看見彼此的共同工作，沿專案、時間、文件、財務與承諾穿梭。

本階段完成可以實際操作、兩種資料模式都完整的 UI；不以真實資料庫／對外整合完成度當作這一階段的驗收目標。

1. 本次及前述使用者明確決定：[decisions.md](../03_feature-reference/REF-004_yuanzhan-operating-interface/decisions.md)。
2. 原始[情境筆記](../03_feature-reference/REF-004_yuanzhan-operating-interface/scenario-notes.md)。
3. [REF-004](../03_feature-reference/REF-004_yuanzhan-operating-interface-sources.md) 中的 v2 提案、v3 CRUD、v4 書寫式、v5 兩人原型，提供公司功能與互動細節。
4. 已選定[整合 v2](../03_feature-reference/REF-004_yuanzhan-operating-interface/integration-v2/index.html)定義空間接合；其簡化表單不能取代原始書寫式編輯要求。
5. 既有程式與 ARC 文件提供接合條件。來源中的命令、固定日期、合約數字與計算公式不是本次新操作授權。

## 2. 空間、作者、共享

- 個人空間：本人私人日誌、個人研究、生活、個人財務。這些模組獨立演化；本階段只作必要切換與隔離，不全面重做私人模組。
- 圓展空間：成員各自的工作日誌、共同工作與公司營運模組。「我的／Lily／全部」依作者篩選。
- 工作直接建立在圓展。無需先寫私人筆記再搬移為公司資料。
- 一般工作預設 `company-internal`；受限專案／明確私人紀錄／薪資等採較窄範圍。作者、負責人與讀者分開。
- 互看不等於任意修改或核准。UI 能展示角色差異與禁止操作的原因，但本階段的角色切換僅是 fixture 模擬，不聲稱後端隔離完成。
- 本階段不新增外部客戶、跨公司或公開訪客的可用業務入口。

## 3. 共用介面原則

1. 大概念 → 子分頁 → 一個主操作面 → 抽屜／彈窗處理細節。
2. 以書寫、大綱、表格、時間線與文件對照承接操作。卡片只用於有意義的群組，不堆模組摘要牆。
3. 明確的主操作與下一步；離開抽屜後回到原篩選、捲動位置和焦點。
4. 日誌的文字區塊可明確賦型為 Standup、Issue、Todo、Decision、Expense 等。AI 推測不得自行把文字變成正式物件。
5. 狀態、專案、負責人、日期等關鍵資訊在列表中可掃描；詳情才下鑽。支援搜尋、標籤、反向引用與鍵盤操作。
6. 同一物件一份狀態，日誌、專案、時間線皆為引用。不能另外維護多份待辦或帳本副本。
7. 每個工作面都要有 loading、empty、no-results、invalid-input、not-found、forbidden、missing-source 與正常資料狀態中適用的部分。
8. 一處簡短標示「介面示例」及重置方式。env 名稱、資料架構、launch prose 放文件或開發診斷，不占一般工作畫面。
9. 選定本方向後，公司工作台採情境分頁；既有 ARC-038 的固定五分頁只保留於未納入本次重構的模組，不強制將所有公司工作面套成「專案／AI／紀錄／邊界」。

## 4. 情境與 UI 完成範圍

| 情境 ID | 觸發與工作面 | 本階段需可操作的結果 |
|---|---|---|
| YZ-S01 | 開始一天，進入工作日誌 | 日期選擇、純文字／標題／清單縮排、Standup 模板、`/` 元件選單、tag／物件引用、作者視角、連續回顧；輸入時決定紀錄類型及範圍 |
| YZ-S02 | 看清今天與目標 | 今日一頁呈現前週／昨天／今天／未來、公司與專案目標、WIP／阻礙；可跳到同一個工作詳情 |
| YZ-S03 | 專案推進與同事討論 | 專案總覽、階段／交付標準、階層聊天室、訊息／附件、Issue／Todo／Decision 建立與更新；日誌與討論引用同一工作 |
| YZ-S04 | 安排公司節奏 | 專案／日常／行政三層時間線；新增、編輯、刪除、星標、詳情、日期篩選；來源承諾事件展示履行／協議變更分支 |
| YZ-S05 | 從各處找文件 | 以公司文件庫統一索引聊天室／日誌等入口的示例附件；分類、標籤、搜尋、版本、來源與被引用處 |

| YZ-S07 | 記帳、憑證與對帳 | excel-like 列／欄操作、交易詳情、多憑證引用、憑證到交易雙向跳轉；銀行明細匹配／差異、圖表及質化說明 |
| YZ-S08 | 報帳、人事、預算 | 分頁操作報帳狀態、人員薪資／獎金試算、專案預算與實際分類；報帳連結僅本機預覽，不建立公開 token |
| YZ-S09 | 判斷容量與交期 | 每人週配置與合計驗證、Size／WIP、開始／完成時間、Throughput／Cycle Time；有樣本展示分布，無樣本顯示不足，不捏造預測 |

| YZ-S11 | 私人與公司切換 | 不同模組選單、分開紀錄與草稿；個人只見本人，圓展按角色／範圍顯示；切換不搬移紀錄 |

## 5. 兩種資料模式是每頁共同要求

唯一規格為 [ARC-040](../02_architecture-and-rules/ARC-040_yuanzhan-ui-data-mode-contract.md)：

```dotenv
PERSONAL_OS_UI_DATA_MODE=showcase
# 或
PERSONAL_OS_UI_DATA_MODE=empty
```

- `showcase`：完整、連貫、適量的虛構營運資料，能走完上述工作情境；具一般、例外、長文字、缺件與受限案例。
- `empty`：所有業務集合初始為空，無示例專案、日誌、訊息、帳目、檔案、指標、提醒、預填草稿。保留身分／空間外殼、導覽、類型選項、欄位與第一筆新增入口。
- 兩者使用相同頁面、DTO 與 CRUD 操作；只有初始資料不同。empty 中新增第一筆資料後可繼續操作，不是永久空白截圖。
- `empty` 是 UI 初始情境，沒有清除資料庫的含義。登入／資料來源／權限／是否為正式環境都不由此 env 決定。
- 每頁完成必須兩種模式各過一次；只有展示模式好看不算完成。

## 6. 本階段與後續正式化

| 本階段 UI-only | 後續正式化 |
|---|---|
| fixture／empty factory → view model → 記憶體互動 | Prisma、BFF、Server Actions 與正式資料持久化 |
| 同一 UI store 內引用更新及角色預覽 | 兩人不同瀏覽器真實同步、服務授權與負向測試 |
| 本機示例附件／版本／核准與封存流程 | R2 上傳、雜湊、不可變封存、正式稽核 |
| 表格、計算與狀態流程模擬 | 真實對帳、薪酬核准、付款及對外報帳入口 |
| 空／滿兩種資料、操作、桌機手機與鍵盤證據 | Auth／Work／deployment 的正式上線證據 |

重整可重置為當前模式；同一頁面工作階段的模組／空間切換保留各自草稿。正式持久化不列為本階段通過條件。

## 7. 階段完成定義

- 所有 YZ-S01–YZ-S12 對應 UI 切片完成、雙模式可操作、跨視圖引用不分叉。
- 經過 [ACC-008](../08_acceptance-and-qa/ACC-008_yuanzhan-ui-dual-mode-acceptance.md) 的桌機／手機／鍵盤／錯誤／隔離模擬檢查。
- 與個人模組、既有正式 Work、auth、storage 的邊界沒有被 UI 模式切換繞過。
- 每頁的細節缺口在實作前按研究輪次處理；不以骨架或「規劃中」作為本階段九個工作面的最終交付。
- 不因此提高正式 launch level，不宣稱 DB-backed／實際多人上線。

## 8. 2026-09-13 自主實作收斂

以 D09 為準：工作日誌直接即時更新，作者改正文、負責人改進度、同事留言。管理者例外依 ARC-040 第 6 節明列。Scope 為 UI-memory，跨瀏覽器同步與正式核准另行驗收。

套用現有 shadcn/Base UI、Tiptap、React Aria 日期／數值控制；維持現有 ThemeProvider 與 tokens。Magic UI 已評估，本次沒有需要另加動畫依賴的情境。公式保留於帳本並即時計算；手機支援日誌／留言／專案／時間線與查找，財務大表格及 Evidence 整理以桌機為主。

路由 `/company/operating`；個人其他模組連回既有頁面，不宣稱那些舊頁面也完成本次雙模式。詳細可重跑步驟與本期限制見 [預覽指南](../03_feature-reference/REF-004_yuanzhan-operating-interface/ui-preview-guide.md)。
