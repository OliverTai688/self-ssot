公司如果要營運起來的話，會需要哪些介面，我現在知道的有

1. 行事曆（把專案的和公司日常節奏的行事曆放上去，也可以對齊每週執行），並且是對應到計劃（如 Lily 的工作合約裡面就有一些時間的承諾）
2. 專案訊息結構（如 HandBook），每個專案層級都有自己的聊天室，可以訊息和上傳檔案，聊天室中也可以建立議題 Issue 和 Todo 的來著手進行追蹤處理
3. 個人會需要一個類似 Obsidian 的日記工作區，可以如圖自由的 tag 專案或聊天室或 Issue、Todo，以時間序的方式幫助個人工作者推論
4. 需要財務的頁面，很好的紀錄每筆內帳和電子發票還有預算和核銷的流程，然後每月可以跟銀行的簿子明細進行對帳，再也包含公司層級和專案層級的財務預算與實際花費的模組
5. 整體後方應該有個類似自動幫我整理成公司雲端資料夾的分類和儲存，contract、proposal、material、yzedtech_brand 之類可以快速貼標籤，也可快速找尋引用，並且也可以有文件的版本控制更新，這些文件的上傳區域可能在聊天室，但是有一個整合的雲端資料夾幫我整理公司龐大多人協作檔案的部分

目前的各介面比較像是卡片，但是公司運行我們會思考的推論比較像是從情境出發，就像是我們可以把日記就是進入端口，甚至日記就可以有每日的 Standup 的 component，可以叫出 component 進行填寫更新，然後日記也可以建立 Issue、Todo 等 component。

再來是第二重要就是看專案總覽和時間線，以此了解整個公司的行事曆包含專案層面、日常層面有沒有關鍵的時間，這個時間線可以 CRUD，然後也可以換成星星樣式代表說這個項目特別重要，點進去則是可以編輯日曆的詳細的情況，日常層面就是公司的 cowork，或是公司會議、活動（如學習日）等，最後是行政層面，那就會是像是發薪日、勞健保繳費等提醒。

然後 Evidence 的部分，應該是像是建立一個 repo，會在專案執行過程中，或是要結束的時候，我們可以把一些文件選擇作為專案的部分，定義資料夾結構，放入各種文件進行整理，或是寫一個 Readme、補充 docs 材料，就像是 GitHub repo 專案那樣去結束專案，這樣專案結束時或是告一個段落需要先整合該 Evidence 可以像是 GitHub 那樣進行版本的演化管理，最後變成一個可記錄可審核的 Evidence repo。

然後今日一頁會比較像是用時間線來看到，我前一週、昨天、今天預計、未來記得要做的事情，也就是用過去現在與未來作為敘事，公司營運目標和專案目標作為對齊的工作台，讓我可以看到我的行動層和目標層可以對齊。

財務應該會是一個可操作的表格（excel-like）、圖表洞察層（包含要回答的問題的圖表與質化文字說明），和一個發票檔案層，可能是圖片加上文字的發票庫，然後發票庫和表格可以互相對應，表格可以找到項目對應的多個圖片、PDF 或文件檔案，而發票庫也可以點選查看詳細資訊跳到表格的那個項目。

再來才會是有一個獨立的分頁工作台用來如進行報帳表格操作、發布報帳連結、報帳紀錄，然後有一個獨立的分頁工作台用來進行人事的計算，包含我的薪水、員工的薪水和獎金，然後有一個獨立的分頁工作台用來進行對專案預算和目前實際花費的項目與金額對比。

然後關於容量與工時應該也是會有我的和員工（Lily）的，然後容量與工時應該會從專案那邊就有一個項目，概念會套用：

> Capacity → Size → WIP → Throughput → Cycle Time → Milestone Forecast

跑個 4～8 週以後，你自然會知道：

```text
員工 A 平均每週完成：3 M + 2 S
M work Cycle Time：P50 = 2.1 days / P85 = 4.2 days
```

這時候你才真正開始擁有「公司自己的 Capacity Model」。

最後就是有一個頁面專門進行文件合約承諾數字的調查，應該會是文件的 list，然後點進去左手邊會是文件內容，右手邊則是可觀測數據的相關紀錄，有些則是要團隊在每個月回顧的時候手動加上去的 log 來進行確認，並且分為內部承諾和外部承諾，以此來管理說公司說到的有沒有做到。

然後介面整體不要多張卡片，而是用一個大概念分分頁子概念再包一個主操作與 pop up 子操作，讓我可以一次專注一件事情並且很好穿梭在多階層的概念系統中選擇操作紀錄並了解頁面之間連結現實公司情境的概念。
