模組分開演化的實際意思

各空間可有不同導覽、啟用模組、資料規則、設定與版本節奏。可共用編輯器外觀，但私人日誌與工作日誌各自維護服務與資料契約。

模組間透過明確的 ID 與服務契約引用。查詢、搜尋、快取、附件及反向連結都帶空間範圍；切換器只呈現使用者已有權進入的空間。

現有個人 Finance 不能直接改成公司共用帳本。公司財務需獨立定義交易、憑證與核准模型。

目前維持單一 app，先建立模組邊界

兩個空間可以先在同一個 Next.js 應用內，以 personal／company 領域目錄與服務分開。不同模組可獨立開發，但同一 app 仍一起部署；需要獨立部署時，再評估多 app 與 monorepo。

這是依現有專案與你的需求提出的架構建議。pnpm workspace 可管理同 repository 的多套件；工具的加入時點取決於實際共用套件或多應用需求。

第一個切片：在圓展直接完成一次工作紀錄。

01

空間與模組選單

沿用現有 Workspace，切換個人與公司選單，分開保留各空間的輸入草稿與頁面狀態。

通過條件

公司紀錄不出現在私人日誌，切換不誤寫到另一個空間。

02

公司工作日誌的輸入契約

作者、日期、類型、專案、可見範圍在保存時確定。待辦與議題在同一操作建立對應物件。

通過條件

一筆輸入可在工作日誌與專案找到；重複送出不產生重複任務。

03

兩人協作與來源連動

宇星撰寫並指派 Lily；兩人按權限看見同一個工作，更新回到日誌引用。

通過條件

非成員、其他專案與工作草稿隔離；作者與負責人區分清楚。

04

各空間擴充下一個模組

公司逐步接文件、承諾與營運；私人空間依自己的節奏發展。

通過條件

一個模組升級不強迫另一個空間採用相同工作流程。
