## 3. 三輪研究

### 第一輪：本地程式與資料
- `projPicker()`（凍結原型）把每個專案畫成 `.seg` 裡的一顆按鈕；`pm-shell.source.js` 的 `pmHead()` 原樣沿用。
- `operating-store.service.ts` 的專案讀取只回 11 欄；`legacyFolderNo`／`priorityTier`／`nextAction`／`description` 不在其中。`applyProject()` 也不寫它們。
- `pm-primitives` 已有 `pmRail`、`pmTable`、`pmRows`。`pmTable` 的儲存格只吃純文字、不支援分組，所以總表另寫一個列元件，沿用同一組 token 與髮絲線語彙。
- 交付標準在 database 模式不會持久化（`PROJMOD-005`），不該被推薦成新專案的第一步。
- 側欄按鈕與其他模組的深連結呼叫的是同一個 `nav('project', 0)`，從參數分不出來。

### 第二輪：成熟產品怎麼做
- **Linear**：專案清單可用 list／board／timeline，可依 status、lead、target date、activity 分組；專案總覽是摘要、屬性、文件與連結、里程碑，屬性在側欄。（[Linear Docs · Projects](https://linear.app/docs/projects)、[Project views](https://linear.app/changelog/2023-05-25-project-views)）
- **Asana Portfolios**：一張清單看所有專案的狀態、進度、到期日與負責人，可加自訂欄位（預算、優先度）；目的是「一眼看出哪個 on track、哪個 at risk，再點進去」。（[6 tips to use portfolios](https://asana.com/resources/tips-for-portfolios)）
- 共同點：**先總表、再專案**；一列一個專案；狀態是分組依據；每列帶一個人寫的短更新。

### 第三輪：空白狀態與資訊量
- NN/g 對複雜應用的空白狀態三條：說明系統狀態、提供學習線索、給直接可走的路；避免完全空白或只有說明沒有動作。（[Designing Empty States in Complex Applications](https://www.nngroup.com/articles/empty-state-interface-design/)）
- 套到這裡：五個空白區塊各說一次「還沒有」不如一張設定清單 —— 每一項是一句用途加一個入口，做完打勾。

## 4. 提案（已採用）

**A. 專案總表**：從側欄進「專案」先看到所有專案。
- 依狀態分組：進行中 → 驗收中 → 商機 → 已結案。預設範圍「進行與洽談」，已結案另一個分段。
- 一列：資料夾序號、專案名稱、客戶、階段、重要度（五格）、下一步、待處理件數、負責人。
- 組內排序：重要度高的在前，同級依資料夾序號。
- 上方一行數字：進行中／驗收中／商機／待處理／沒寫下一步／已結案。
- 搜尋涵蓋名稱、客戶、序號、下一步。

**B. 專案標題列**：取代那排按鈕。
- 「所有專案」回總表；專案名稱 19px、序號、狀態、重要度；第二行客戶、負責人、類型、開始日。
- 「切換專案」是依狀態分組的原生下拉選單 —— 15 個選項用原生選單最省空間，也自帶鍵盤與行動裝置支援。

**C. 總覽**：
- 最上方是「下一步」：一句話、說明、修改入口。
- 剛建好的專案（沒有分期、硬碟、會議、任務、交付標準）只顯示設定清單四項：寫下一步、分期、啟用專案硬碟、記第一場會議。
- 有內容的專案維持原本的區塊，重點數字列拿掉已經移到標題列的「狀態」。

**D. 字級**：總表與標題列 12.5–14px（專案名稱 14px、標題 19px、下一步 16px），其餘 pm-* 版面不動。

### 否決的做法
- **看板（依狀態分欄）**：四欄各放一疊卡片，放不下「下一步」這種一句話的欄位，而且專案不常換狀態，拖曳的價值低。
- **左側常駐專案清單（三欄）**：工作台已有一條側欄，檔案與會議分頁內又各有一棵樹，再加一欄會把主內容擠到剩一半。
- **時間軸／甘特當首頁**：只有 `01` 有完整日期，其餘 14 個專案會是一片空白。
- **把生命週期（`lifecycleStage`）畫出來**：它與工作台的狀態是兩套詞彙，使用者改狀態時不會同步，等 `PROJMOD-006` 決定權威來源再做。
- **用 `pmTable`**：不支援分組與多行儲存格。

## 5. 資料契約變更

| 方向 | 內容 |
|---|---|
| 讀 | 專案列多四欄：`no`（`legacyFolderNo`）、`tier`（`priorityTier`）、`next`（`nextAction`）、`desc`（`description`） |
| 寫 | `applyProject()` 在列帶著 `next`／`tier`／`desc` 鍵時寫回；**沒有那個鍵就不動**，所以還沒更新的分頁不會把值清空。`tier` 只收 1–5，其餘存 null。`no` 唯讀 |
| Schema | 無變更，無 migration |

## 6. 驗收條件

1. 從側欄進專案，看到的是總表，不是那排按鈕。
2. 15 個專案依狀態分組，每列看得到客戶、重要度、下一步。
3. 點一列進專案；標題列的「所有專案」回得來；「切換專案」列出全部。
4. 其他模組的連結仍然直接落在專案上，舊分頁 index 的重導不變。
5. 新專案的總覽是設定清單，沒有空白區塊。
6. 填寫下一步之後，總表與總覽都看得到，重新整理後還在。
7. 390px 寬不出現橫向捲軸。

## 7. 沒做的

- 總表的欄位自訂、排序切換、看板與時間軸檢視。
- 在總表列上直接編輯下一步（目前要進專案或開表單）。
- 生命週期顯示（`PROJMOD-006`）。
- 其餘 pm-* 版面（計劃、檔案、會議、對話）的字級。
