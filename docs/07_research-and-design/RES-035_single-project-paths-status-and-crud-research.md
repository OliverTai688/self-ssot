## 1. 路徑與現況分析

以示範資料的「柏翰 · Google Workspace 導入」逐頁截圖（`shots/before-*.jpg`）。

| 路徑 | 現況的問題 |
|---|---|

### 本輪最重要的發現：任務負責人沒有落地

`operating-store.service.ts` 讀任務時 `owner: ""`，`applyIssue()` 也不寫它，`ProjectTask` 沒有這個欄位（既有待辦 `PROJMOD-005`）。前端的 `editable()` 在沒有作者與負責人時退回預設席位 `yz`，所以**重新整理之後只有 yz 勾得掉任務，Lily 一件都動不了**。「讓兩個人都能管理專案」在這一點上是壞的，與介面無關。

## 3. 決策摘要

| 路徑 | 採用 | 不採用與原因 |
|---|---|---|
| 狀態變更 | **A 就地小視窗**：選狀態 → 理由 → Enter | B 整張表單：改五個任務要開關五次。C 即改可復原：理由變成事後補，實際上不會有人補 |
| 初始化 | **A 範本一次建好**（一期＋五階段＋里程碑），入口在設定清單與計劃的空白狀態 | C 複製另一個專案：目前沒有任何專案有完整結構可複製 |
| 總覽 | **A 現有版面＋狀態可點＋狀態紀錄** | B 右側屬性欄：與標題列重複。C 期階梯為主：14／15 個專案未分期 |
| 計劃 | **A 階層樹＋狀態可點＋行內新增** | B 工作流看板：丟掉「期」，拖曳沒地方寫理由。C 試算表：壓平階層 |
| 工作 | **A 一張清單可換分組，預設依負責人** | B 看板：拖完才問理由。C 兩人兩欄：綁死在兩個人 |
| 會議 | **A 維持，缺結論可點** | 時間軸與表格：一個專案的會議不到 10 場 |
| 檔案 | **A 維持，本輪不改** | 縮圖格狀、依種類分區 |
| 對話 | **A 狀態變更成為主頻道的系統訊息** | B 另開動態分頁；C 只放總覽 |
| 財務 | **A 維持，本輪不改** | 期款狀態列：會動到現金推演與結帳鎖，屬於金流 |

### 理由的規則

往前推進（待辦 → 進行中 → 完成）理由可略過；**往回走、結案、取消、退回一律必填**。往前是例行，往回才需要解釋。必填到所有變更會讓人亂填，反而失去價值。

### 理由存在哪

每一筆變更寫成專案主頻道的一則訊息：`origin = SYSTEM`、`messageType = status`，`meta` 帶 `{ kind, ent, ref, name, from, to, reason }`。

- `ProjectChatOrigin.SYSTEM` 在 schema 的註解就是「系統訊息（階段完成、里程碑達成）」，這是它原本的用途。
- 兩個席位都讀得到（稽核軌跡只有負責人能看）。
- 同一筆 `commit()` 裡與狀態本身一起送出，不會出現「狀態改了、紀錄沒寫」。
- `commit()` 效果的第一行是「狀態 A → B｜理由」，所以稽核軌跡的 `detail` 也自動帶著理由。
- **否決：新增 `project_status_changes` 表。** 多一張表、多一條讀寫路徑，而它能回答的問題與上面完全相同。

專案還沒有聊天室時，第一次改狀態會在同一筆命令裡建立主頻道（伺服器的套用順序已把 `chatChannels` 排在訊息之前）。

### 階段的狀態

階段沒有狀態欄，狀態由起訖日與里程碑推導。它仍然可以點：

| 選 | 實際發生的事 |
|---|---|
| 進行中 | 開始日拉到今天；結束日若已過，延到一週後，並在效果裡明說 |
| 已完成 | 結束日收在昨天，下一個階段從今天開始。底下還有里程碑沒達成時不能選 |
| 未開始 | 開始日改為明天 |

| 項目 | 內容 |

| Migration `20261009090000_project_task_owner` | `project_tasks` 新增 `owner_key TEXT`、`started_on DATE`，皆可為 NULL，無回填 |

## 5. 驗收條件

1. 專案、期、階段、里程碑、任務、審核結果的狀態籤都可以點。
2. 往前推進可以不寫理由；往回走、結案、取消、退回不寫理由不放行。
3. 每一筆變更在總覽的狀態紀錄、對話的主頻道、該筆的小視窗裡都看得到誰、何時、從什麼改成什麼、為什麼。
4. 新專案可以用範本一次建好第一期、五個階段與里程碑。
5. 在里程碑底下、階段底下、工作清單最上面打一行字按 Enter 就建立，游標留在原地。
6. 任務的負責人點頭像可以換，重新整理後還在；Lily 改得動自己的任務、改不動別人的。
7. 工作清單預設依負責人分組，狀態顯示中文。
8. 375px 寬小視窗貼底、沒有橫向捲軸。
9. 舊分頁 index 的重導、審核的送審／通過／退回按鈕行為不變。
