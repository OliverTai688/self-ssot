R1 · 本地 PRD／程式碼契合

這頁其實已經有規格在等它

RES-002 的 resource index 條款：「search, filter, sort, paginate, select, bulk-act, and open detail」。 ARC-030 更硬：模組索引必須先映射到共用契約，而且「Building each module index independently. Rejected.」

採用：照 ARC-030 的契約形狀宣告這一頁（即使目前是 prototype 記憶體資料）。 否決：自己發明一套索引欄位與互動。
R2 · 對照產品與外部研究

關鍵字搜尋不是答案

Teevan 等人（CHI 2004）：即使一開始就知道要找什麼，只有 39% 的搜尋用關鍵字； 人偏好沿著熟悉的來源一小步一小步走。Dumais 等人（SIGIR 2003）：使用者偏好結果依日期而非相關度排序。

採用：瀏覽路徑與搜尋同等重要；預設依時間排序；每列都給「回到來源」這條第二條路。 否決：把搜尋框當成唯一解法。
R3 · 資料／BFF 邊界

標題不是識別碼

RES-018 定了參考碼格式 {TYPE}-{ORIGIN}-{SEQ:6}-{YYYYMMDD}， 規則是「建立時指派一次、永不重生成、改顯示名稱不得更動」。 但 docObjectName() 每次渲染都會用第一行內容重算標題 —— 正是 RES-018 要防的「引用失效」。

採用：列上同時顯示穩定參考碼（等寬可複製）與會變動的顯示名稱。 否決：只顯示自動標題就當作物件身分。
R4 · 風險／驗收邊界

唯讀索引，不開寫入口

ARC-030 §8：批次寫入在稽核與核可機制存在前一律拒絕；/company 屬高風險模組。 REF-003：標籤流沒有自己的 Screen ID，屬 UI-088 的分頁，且 UI-088 已 COMPLETED → 這是 Revision Mode。

採用：唯讀索引；列動作只有「開啟物件／開啟來源日／複製參考碼」。 否決：在索引上做批次刪除、批次改狀態、批次匯出。

每一條研究，改了介面的哪一處研究不是歸檔，是要留下可驗證的東西

來源發現介面上的具體改動
Teevan 等人，CHI 2004Orienteering behavior in directed search 已知目標時仍只有 39% 用關鍵字搜尋；人常把目標與「某個來源」綁在一起，沿路徑走。 「即使看到檔名，也要看到同資料夾裡其他名字才確定是它。」 每列給兩個目的地：開啟物件 ↗、開啟它誕生的那天日誌 ⤵。 並且預設依日分群而不是平鋪 —— 讓你看得到「同一天還有什麼」。
Dumais 等人，SIGIR 2003Stuff I've Seen 使用者偏好結果依日期排序而非相關度；因為對「大概什麼時候碰過它」有概念。 預設排序 = 建立時間新到舊，連搜尋結果也一樣（不做相關度排序）。
Ringel 等人，2003 在結果旁加上時間地標（那段期間發生的事）可量化地改善找回效率。 月份分組列與時間軸的每一天，都掛上當天的日誌標題當地標 （資料已存在：DB.journal[k].title）。「8/21 供應商議價週」比「8/21」好認太多。
Allen, 1989 人回憶內容遠勝於回憶名稱、編號、存放位置這類形式描述。 搜尋比對範圍含各段落內文，不只標題；命中時列下方顯示內文片段並標亮。
Mackenzie 等人，2019 純時間排序的 email 找回，目標越舊失敗率越高。 時間排序不能單獨存在 —— 型別 facet 與月份分組是把三個月尺度切小的必要條件，不是裝飾。
Whittaker 等人，2011 機會式搜尋主導找回行為，手動建資料夾與標籤的效益低。 頁名從「標籤流」改為「物件索引」。不建手動標籤體系，改用系統本來就有的屬性 （型別、時間、作者、來源日）。
NN/g · Filter categories and values 篩選值要「可預期、無術語、依使用者優先序排列」。 chip 文字用 Standup／會議紀錄／1:1，不用 doc_object 這種內部 key； chip 帶數量；排序依實際使用頻率而非字母。
SaaS data table patterns 識別欄放最左；表頭 sticky；列動作直接露出，不要藏進選單； 「參考與稽核」類表格用分頁而不是無限捲動。 欄序＝型別→物件（識別）→建立時間→來源日誌→最後更新→動作；表頭與月份列都 sticky；分頁而非無限捲。
RES-002 / ARC-030 / ARC-012（本地） resource index 必備 search／filter／sort／paginate／detail； records 頁「不要做成裝飾性活動卡牆」；mock 資料不得看起來像正式資料。 密集表格為主、時間軸為輔；右上角常駐 Prototype 標記； 空狀態寫清楚會出現什麼與下一步。
RES-018（本地） 參考碼建立時指派一次、永不重生成；以等寬可複製徽章顯示於顯示名稱旁，不取代名稱。 名稱後加參考碼徽章。附帶發現：目前 DOC-MEETING-x9k2ab 用隨機字尾， 不符合 RES-018 的 {SEQ:6}-{YYYYMMDD} 格式，需要一併校正。

這些看起來合理，但研究不支持

  • 只做搜尋框，不做瀏覽路徑。Teevan 2004：已知目標時仍有 61% 的搜尋不用關鍵字。 只給搜尋等於把六成的使用情境丟掉。
  • 搜尋結果依相關度排序。Dumais 2003：使用者明確偏好依日期。這裡是個人／兩人語料， 不是網頁檢索，相關度排序反而讓人失去方位感。
  • 建一套手動標籤／資料夾。Whittaker 2011：手動歸檔的投入報酬低，機會式搜尋主導找回。 也因此「標籤流」這個頁名該退場。
  • 把索引做成卡片牆。ARC-012 §5：「Avoid making records a decorative activity card wall.」 AGENTS.md §12 也要求記錄頁優先用可篩選表格與時間軸。
  • 自訂密度切換／自訂欄位設定面板。全域已有 S.compact； 多一個區域性控制只會讓兩處不同步。
  • 在索引上做批次操作（批次刪除／改狀態／匯出）。ARC-030 §8 在稽核與核可機制到位前一律拒絕， 且 /company 是高風險模組。
  • 只顯示自動標題當物件身分。RES-018：顯示名稱會變、參考碼不會； 而 docObjectName() 恰好每次渲染都重算標題。
  • 給標籤流一個新的 UI ID。REF-003:202：「UI-088 的 tabs／drawers 是同一工作台的依賴，不新增假 UI ID。」

索引契約ARC-030 形狀。即使現在是記憶體資料，先宣告，之後接 DB 不用重畫

ObjectIndexContract
  searchable   : 顯示名稱、各段落內文（TEXTY 區塊的 text）、參考碼
  filters      : 型別（多選）｜作者｜日期區間｜是否仍有來源日誌行
  sorts        : 建立時間 ↓（預設）｜最後更新 ↓｜型別＋建立時間
  columns      : 型別 · 物件（名稱＋參考碼）· 建立時間 · 來源日誌（日期＋地標＋行號）· 最後更新
  grouping     : 月份（預設）｜日（時間軸檢視）｜無
  pagination   : 每頁 25，頁碼式（參考／稽核用途，位置需可預期）
  rowId        : 物件 id（穩定）
  rowActions   : 開啟物件 ↗｜開啟來源日誌那一行 ⤵｜複製參考碼
  bulkActions  : 無（ARC-030 §8：稽核與核可到位前拒絕批次寫入）
  detail       : 沿用既有 drawer / 獨立頁，不另開新的詳情面板
  states       : empty（說明會出現什麼＋前往今天）｜loading｜error｜
                 partial（來源日誌行已刪除 → 標示但仍列出）
  dataMode     : prototype（記憶體）— 右上常駐 Prototype 標記，不得看起來像正式資料

這份契約對應 ARC-030 的十項要求。本階段是 UI-only prototype， 不接 Prisma、不做服務層授權、不新增公開輸出 —— 但欄位與動作的形狀先對齊，未來換成 DB-backed 時不用重畫介面。

驗收條件可逐條勾，不是感覺對不對

  1. 型別正確。Standup／1:1／會議紀錄／回顧／研究筆記在索引上顯示正確名稱與人話型別標籤， 沒有任何一列顯示「已刪除」除非物件真的被刪。
  2. 兩條路都通。點 ↗ 開啟物件本身；點 ⤵ 跳到該物件誕生那天的日誌並定位到那一行。
  3. 孤兒物件仍在。手動刪掉日誌裡那一行 obj 區塊後重新整理索引，該物件仍列出， 來源欄顯示「來源日誌那一行已刪除」。
  4. 段落內召喚也列得到。在 Standup 的某個段落裡用 # 召喚一個工作物件， 該物件出現在索引，來源欄指到那份 Standup。
  5. 搜尋打得到內文。用只出現在某份會議紀錄第三段的詞搜尋，該列命中並顯示標亮片段。
  6. 時間誠實。新召喚的物件顯示到時分；沒有 bornAt 的舊物件以淡色只顯示日期， 不得偽造時刻。
  7. facet 數字正確。chip 上的數量等於套用該型別後的列數；0 筆的型別淡化但仍顯示。
  8. 空狀態可讀。在 ui-empty 環境下顯示空狀態文案與「前往今天的日誌」，不是空白表格。
  9. 四主題可讀。white／orange／black／brand 四個主題下文字對比與 chip 顏色皆可讀， 無任何硬編碼 hex。
  10. 圖示不空。新用到的 icon key（search／x／sort） 已加進 icon 表，畫面上沒有空白方框。
  11. 390px 不爆版。手機寬度下表格可橫向捲動、文字不溢出容器。
